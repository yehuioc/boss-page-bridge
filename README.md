# Boss 浏览助手

连接普通 Chrome 中你自行登录的 BOSS 直聘标签页，读取职位、整理候选，并通过 Codex 订阅模型理解 JD。初步问询先展示职位、HR 和发送原文，确认该批后才执行。

当前版本 **0.7.2**，采用原生固定侧栏与 Manifest V3 后台。无需 CDP、debugger、Playwright 或开发者工具，也不调用 Boss 私有接口。项目不是 BOSS 直聘或 OpenAI 的官方产品。

## 能做什么

- 搜索、页面已提供的城市和条件筛选，读取职位列表及两种详情布局，支持页面、列表与详情分区滚动、返回和刷新。
- 有界采集职位，按链接去重并保存原文、条件和出处，导出 Markdown、CSV、JSON。
- 模型解释实际职责、证据与未知条件。未写远程或描述简短不直接排除；明确冲突必须给出对应原文。
- 配置初步问询模板，每批最多5个对象。预览职位、HR、文本及默认招呼影响，确认后逐项核对和发送。
- 读取选中 HR 的已加载文字回复，结合已有 JD 更新判断。不会自动发送后续建议，不操作发简历、换电话、换微信、投递或收藏。

**真实验收边界：**搜索采集、模型读取真实 JD、单个 HR 的默认招呼与追加问询已分别在真实页面验证。尚未完成“从筛选开始到多个 HR 全部发送完成”的连续真实验收，多 HR 批量调度不能视为已验证稳定。对方新回复到来后的真实模型分析、所有页面变体、长期最小化和跨 Chrome 版本稳定性也未完整验收。本次公开准备只运行合成数据测试，没有操作真实账号。

## 安装与启动

需要桌面 Chrome 116+、Python 3.10+。Python 服务仅使用标准库，无需 `pip install`。Node.js 20+ 仅用于开发测试。

```powershell
git clone https://github.com/yehuioc/boss-page-bridge.git
cd boss-page-bridge
python -X utf8 -B server.py
```

服务默认仅监听 `127.0.0.1:8926`，终端打印首次配对码。不要将服务暴露到公网。保持该进程运行。

1. 打开 `chrome://extensions`，开启扩展管理页的“开发者模式”，选择“加载已解压的扩展程序”，加载仓库的 `extension` 目录。这不需要打开网页控制台。
2. 正常打开并登录 Boss。左键点击工具栏里的扩展图标，打开固定侧栏。
3. 初次使用输入服务显示的配对码，点“连接本机”。后续更新保留配对。
4. 选中需要操作的 Boss 标签页，点“连接当前 Boss 页并开启后台浏览”。读取结果会自动回传，不用手动发送。
5. 更新扩展源码后在扩展管理页重新加载，再打开侧栏连接。服务重启也会使原接管暂停，需要重新连接。

关闭侧栏、切换标签页或最小化不会主动停止已有接管。点“立即停止”才结束接管；浏览器关闭、电脑休眠、账号变化、页面冻结、掉线或执行器中断会暂停，未完成动作不自动重放。原生 worker、独立心跳和会话状态处理不保证页面永不被冻结。

## 模型配置与数据发送

模型能力可选。浏览、保存和规则辅助不需要 Codex 登录。

按 [Codex CLI 官方说明](https://learn.chatgpt.com/docs/codex/cli) 安装 CLI，并使用自己的 ChatGPT 账号登录。启动本机服务的同一环境中运行：

```text
codex login
codex login status
```

侧栏“检查订阅模型连接”核对服务实际运行环境的登录状态。只有当前环境显示可用的 ChatGPT 订阅登录才能调用；项目不复制登录令牌，不自动切换到 API key 或另一种计费渠道。CLI 选项变化可能影响兼容性，失败会明确显示，不以关键词规则冒充模型结果。

**启用采集后的模型分析，或点击模型分析按钮，会将所选 JD、你填写的求职条件和对应 HR 的选定文字回复交给 OpenAI Codex 服务处理。**默认不启用采集后的模型分析。不会发送整个消息列表或简历；文本中可识别的手机号、邮箱与联系方式标记会省略，但不能保证识别所有隐晦联系方式。只在你有权处理这些材料、同意这一数据流向时使用模型功能。

CLI 使用临时会话、只读沙箱、无项目指令和严格 JSON schema；关闭 shell、浏览器、插件等工具。模型只解释给定材料，不能提交任意脚本、选择器或浏览器命令。引用必须存在于对应原文中，职位地址必须与输入一一对应。模型仍可能误判，应展开依据核对。

## 找岗与候选

首次安装不预填个人关键词或学历，远程和兼职条件也不默认勾选。填写自己的关键词、城市、学历和经验；这些是判断条件，网站筛选是独立可选项，不把个人学历直接强制成网站学历筛选。

点击“开始找岗并保存候选”。每轮最多30个详情、15分钟，每个关键词最多4轮发现滚动，连续两轮无新链接即结束该词。结果只覆盖已加载页面，不代表全站。

“本轮结果”查看最近任务，“已存岗位”查看按链接去重的记录。勾选已有岗位可单独交给模型阅读；模型使用表单当前条件，保留当时分析条件、原文和未知项。JD改变会标记旧判断。采集记录不保证职位目前仍在招聘。

命令行可使用明确合成的示例文件：

```text
python -X utf8 -B control.py search-start --profile examples/search-profile.example.json
python -X utf8 -B control.py search-state
python -X utf8 -B control.py search-library
python -X utf8 -B control.py search-export --format md
python -X utf8 -B control.py search-stop
```

`examples/search-profile.example.json` 不是有效个人档案，使用前应修改。自己的条件请保存到被忽略的 `private/search-profile.json`，不要提交。

## 初步问询与回复

1. 修改并保存通用问询模板，再勾选最多5个已存岗位，点“为勾选岗位准备预览”；也可在消息页选中已有 HR，准备当前 HR 的预览。
2. 准备只读取页面。预览展示公司、HR、职位、实际文本；新联系会注明先触发网站设置的默认招呼，再追加问询。默认招呼内容由网站设置。
3. 核对后点击“确认本批并发送”。批准绑定本次连接、对象、职位、文本和预览版本，15分钟过期；重新连接、修改内容或服务重启不恢复旧批准。
4. 发送前逐项核对身份与输入框。其他草稿不覆盖；与批准原文完全一致的待发送草稿可明确纳入预览。填入后等待网站启用按钮，再次检查停止状态和账号后点击。
5. 每次外部动作先保存尝试记录，使用单次授权。只有新消息编号、批准原文及空输入框对应时才记为已发送，不代表对方已读。发送前明确未点击记为未发送；一旦可能已点击而无法核对，就保留不确定状态并暂停，不自动重发。
6. 在消息页选中对应 HR，点该批次“读取该 HR 回复”。只读取当前加载文字；有本次问询编号时，只取其后的 HR 回复。再点“分析这些回复并更新判断”可生成新判断和建议，不自动续聊。缺少已核对 JD 时保留缺口，不补造职责。

不确定记录可通过只读核对新消息改正，不能拿旧的相同消息冒充本次发送成功。普通 `/control` 入口无法发送问询。

## 浏览和控制入口

```text
python -X utf8 -B control.py status
python -X utf8 -B control.py read
python -X utf8 -B control.py scroll --y 300
python -X utf8 -B control.py scroll --target list --y 1000
python -X utf8 -B control.py navigate --url https://www.zhipin.com/web/geek/jobs
python -X utf8 -B control.py back
python -X utf8 -B control.py reload
python -X utf8 -B control.py stop
```

`status` 可含私人页面与消息，不要把输出贴到公开 issue。搜索和筛选控件引用来自刚读取的 DOM，绑定实际元素、用途、地址、有效期和遮挡状态；失效后须重新读取，不猜测或重放点击。没有任意脚本或任意选择器执行入口。

网页导航限制在正常职位、公司和已识别浏览入口。全部悬停菜单、兼职结算方式与兼职时间筛选尚未适配；不把“已点击”当作筛选成功。城市仅支持当前已观察到的选项，不猜编号。验证码、登录限制由用户在网站处理，不尝试绕过。

## 私人数据与截图

首次启动自动建立被忽略的 `private/`：

| 位置 | 内容 |
| --- | --- |
| `connection.json`、`control.key` | 配对哈希与本机控制凭据 |
| `latest.json`、`captures/` | 页面原文、动作证据及薪资小图 |
| `search/` | 条件、候选、历史采集与导出 |
| `assistant/` | 模型结果、状态与私有 CLI 日志 |
| `inquiries/` | 模板、预览、确认、尝试、回显和对应回复 |

配对凭据还会保存在扩展自己的 Chrome 存储中。仓库不附带用户数据、登录资料、截图或真人聊天；测试全部使用合成夹具。备份私人资料需单独备份 `private/`，Git 无法恢复它。

普通页面读取已渲染顶层 DOM，最多40000字符；消息页只读取选中会话，不读取整个联系人列表或回传其他草稿。跨域 iframe、canvas、封闭 Shadow DOM、未加载虚拟列表和图片消息不保证可读。

薪资含私用区字体字符时不猜数字，优先使用同职位普通正文，必要时只截薪资区域。截图必须处于前台、可见、拥有临时权限的页面；后台或最小化时跳过并说明原因，不抢前台。整屏截图仅短暂用于内存裁剪，不落盘或回传。裁剪小图也属于私人数据，模型文字分析不等于自动识别截图。

服务固定使用 loopback、配对来源与本机控制密钥鉴权。扩展仅申请两个 Boss HTTPS 域和本机地址，以及 `activeTab`、`scripting`、`storage`、`sidePanel`、`alarms`；没有调试器、Cookie、全部网站或全部浏览历史权限。这不构成无法被平台检测或不会触发账号限制的保证。
